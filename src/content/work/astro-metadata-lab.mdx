## Problem

Advice on what belongs in a page's `<head>` is easy to find and hard to verify. Whether a messaging app falls back to the HTML title when Open Graph text is missing, whether an SVG works as a share image, or which icon a browser picks from several candidates depends on the client, and documentation rarely says. Before deciding what a minimal Astro starter should emit by default, those questions needed answers from actual clients.

## Constraints

- Each case had to be an independent page, viewable on its own for favicon, first-paint and mobile viewport observations that an iframe cannot show.
- Values had to be distinguishable at a glance. In the precedence cases, HTML, Open Graph, Twitter card and body text each carry a different marker and image colour, so a preview shows which source a client used.
- Observations come from real browsers and apps on available devices, reported by hand, so every record states what was and was not observed.
- The site is static, with no client JavaScript bundle, and deploys to Cloudflare Pages with the host rules that the HTTP controls need.

## Decisions

- **One catalogue, three views per case.** Every fixture has its own page, a side-by-side comparison with the baseline homepage and a plain-text view of its source.
- **Controls that are meant to fail.** Fixtures include broken images, conflicting tags, duplicate canonicals, a script-end injection in JSON-LD, a real 404, a 302 redirect and a header-only `noindex`, so failure modes are visible rather than assumed.
- **Records separate contracts from observations.** Each case has a results page, and a shared run registry records which client produced each observation. A documented requirement of the Open Graph protocol or Google's guidance is kept apart from what a client happened to show.
- **Checks on the artifact.** The build is verified for every case, source and comparison output, exact fixture HTML, asset bytes, manifest paths, host rules and the absence of a client bundle, including under a subpath.

## Results

Each result links to the case records behind it; the [results index](https://astro-metadata-lab.cevdet.ch/cases/results/) lists every case and the run that produced each observation.

- **Write Open Graph text explicitly.** With only `og:title` removed, Discord showed neither a title nor a description, and with only `og:description` removed it dropped the description, while two other messaging apps filled the missing field from the HTML ([og-no-title](https://astro-metadata-lab.cevdet.ch/cases/results/precedence/og-no-title/), [og-no-description](https://astro-metadata-lab.cevdet.ch/cases/results/precedence/og-no-description/)). With no Open Graph tags at all, Discord did show the HTML title and description ([html-only](https://astro-metadata-lab.cevdet.ch/cases/results/precedence/html-only/)). The recommendation became one shared title and description feeding both the HTML and the Open Graph text.
- **Some tags stay for the protocol, not for an observed effect.** Removing `og:type`, `og:url` or the image dimension tags caused no reported visible change in any of the five link-preview clients tested ([no-og-type](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/no-og-type/), [no-og-url](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/no-og-url/), [image-without-dimensions](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/image-without-dimensions/)). `og:type` and `og:url` stay for protocol conformance; the agreed default leaves the dimension tags out.
- **Prefer an absolute PNG share image.** A root-relative image showed in four of the five clients, and an SVG image only in Instagram ([image-relative](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/image-relative/), [image-svg](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/image-svg/)). A missing image produced no image in three clients and a stand-in in Discord ("Image failed to load") and Instagram ([image-missing](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/image-missing/)). Generated images default to 1200×630 PNG.
- **Escape JSON-LD.** In Firefox, the unsafe control failed to parse, injected an image element and set its runtime flag, while the escaped control parsed with the markup-like text kept as a string ([jsonld-unsafe](https://astro-metadata-lab.cevdet.ch/cases/results/json-ld/jsonld-unsafe/), [jsonld-escaped](https://astro-metadata-lab.cevdet.ch/cases/results/json-ld/jsonld-escaped/)).
- **Build checks alone missed a dev-only failure.** A strict trailing-slash policy made an extensionless asset endpoint reject file URLs in the dev server while the static build emitted the right files; a regression check now exercises Astro's dev route matching ([design notes](https://github.com/cevdetch/astro-metadata-lab/blob/main/src/metadata-cases/design-notes.md)).
- **Clients cut text at different lengths**, so the recommendation keeps full escaped strings and gives writing guidance instead of silent truncation ([long-title](https://astro-metadata-lab.cevdet.ch/cases/results/metadata/long-title/)).
- **LinkedIn's post composer and direct messages showed no preview.** Post Inspector rendered titles and images but never a description ([all-fields](https://astro-metadata-lab.cevdet.ch/cases/results/precedence/all-fields/)).
- The [Astro Minimal Template](https://astro-minimal-template.cevdet.ch/) ships these defaults: one title and description for both the HTML and the Open Graph text, `og:type` and `og:url` without dimension tags, a generated 1200×630 PNG, untruncated text and escaped JSON-LD.

## Next

- Diagnosing why LinkedIn's post composer and direct messages showed no preview, which the Inspector results did not explain, remains open.
