## Problem

Arch Linux's official packages are built to work everywhere, so a desktop that runs only on Wayland still pulls in X11 libraries, XWayland, GLX and audio backends it never uses. Removing them means rebuilding the libraries and applications that depend on them, and then keeping every rebuilt package current with both its upstream release and Arch's own packaging.

## Constraints

- Wayland only: no dependency on X11, Xorg or XWayland, and no graphical application that needs XWayland to run.
- PipeWire only for audio: a native PipeWire backend, or PulseAudio and ALSA clients routed through `pipewire-pulse` and `pipewire-alsa`. The PulseAudio daemon and JACK are excluded, including PipeWire's own JACK bridge.
- Vulkan and EGL for graphics, with OpenGL through EGL and no GLX.
- Sources are official release archives or official upstream Git sources, verified by SHA-256 checksums and tested in a clean chroot.
- Replacement packages must stay drop-in: each provides and conflicts with the official package name, so other packages keep depending on official names.

## Decisions

- Each package has its own directory with its `PKGBUILD` and `.SRCINFO`. Starter recipes for CMake, Meson and Autotools set up new packages.
- Each recipe passes its build options explicitly, from a named array such as `_meson_options` or `_cmake_options`. A policy flag can carry a short tag such as `# WAYLAND` or `# PIPEWIRE`, with a longer explanation above any unusual choice, and the tools keep those comments when they propose a new array. The tags are added as recipes are reviewed; FFmpeg, GTK 4 and a handful of others carry them so far. Declaring a dependency is never treated as enabling a feature.
- `waypure-options` discovers a package's build system, release source and Arch package, compares the upstream options of a new release with the previous one and with Arch's packaging, reports removed and deprecated options, and writes a copyable option array. It covers Meson, CMake, Autoconf, Qt 6 and FFmpeg, and reads Cargo and Python dependency declarations. `qt6-options` and `ffmpeg-options` are shorter entry points to the same engines.
- `waypure-audit` checks a recipe's metadata, checksums, dependency policy and replacement declarations, and traces runtime dependencies through local packages. With built archives it inspects ELF links and library names for X11 or forbidden audio libraries. A shared policy file, `waypure-policy.toml`, lists the forbidden package and library families.
- `waypure-build` orders builds by the local recipe graph, which differs from Arch's dependency graph for these packages, reports which packages are stale, and rejects incompatible versions, ambiguous providers and duplicate outputs before building.
- `waypure-validate` validates releases: it builds selected recipes in fresh copies of a clean chroot, runs the archive policy and namcap checks on every output, and writes a receipt with the recipe, source and archive hashes. `waypure-chroot` prepares a separate clean-chroot profile for personal builds tuned to the build machine's processor.
- The tools use the Python standard library, so they need no virtual environment. `pyalpm` adds direct libalpm queries, and `tools/install` links the commands into a prefix.

## Results

- The repository holds rebuilt packages across the desktop stack, from Cairo, GTK and Qt 6 to FFmpeg, mpv, Sway and Zed.
- A GitHub Actions workflow runs the tools' test suite on Python 3.11 and 3.13, checks `waypure-remove-x11` with ShellCheck, and audits the metadata of changed recipes and patches. A second job runs the libalpm tests against temporary package databases in an Arch Linux container. CI does not build the packages.
- `waypure-versions` compares installed and local packages with Arch's repository versions. `waypure-audit-audio`, `waypure-audit-graphics` and `waypure-audit-x11` inspect the installed system read-only and show which packages pull in JACK, GLX or X11 support.
- `waypure-remove-x11` previews which installed X11 packages can be removed and requests their removal through pacman's own confirmation and dependency checks.
