# cevdet.ch

Cevdet Haran's portfolio. This repository is the single source for
[cevdet.ch](https://cevdet.ch/) and for the CV, built with Astro as a static
site and deployed by Cloudflare Pages.

## Requirements

- Node.js 24.8.0 or newer
- Bun, pinned in `package.json`
- Python 3.12 or newer, for rendering the CV: `pip install -r requirements.txt`

## Setup

```sh
bun install --frozen-lockfile
bun run dev
```

## Commands

| Command | Purpose |
| --- | --- |
| `bun run dev` | Run the site locally |
| `bun run verify` | Run every check: types, unused code, tests, a fresh build and the output gates |
| `bun run fetch-facts` | Refresh `src/facts/` from GitHub, npm, the AUR and PageSpeed Insights |
| `bun run cv:private` | Render the full CV, including the fields kept out of the public build |
| `bun run lighthouse` | Build and audit performance, accessibility, best practices and SEO |
| `bun run build` | Build the static site into `dist/` |
| `bun run preview` | Preview the production build |

`bun run fetch-facts` needs a token with read access to the GitHub API:

```sh
GITHUB_TOKEN=$(gh auth token) bun run fetch-facts
```

It measures each Work's site with the PageSpeed Insights API, using the key in
`PSI_API_KEY`, read from the environment or from a gitignored `.env` file.
Without a key, or when the API is unavailable, each site keeps its last scores
and the refresh prints a warning.

`bun run lighthouse` needs a Chrome or Chromium binary. It honours `CHROME_PATH`
when the default is not on the system:

```sh
CHROME_PATH=/path/to/chrome bun run lighthouse
```

## Deployment

Cloudflare Pages settings to apply by hand in the dashboard:

- Build command: `bun run build` (or `bun run verify`, whichever gate the Pages settings currently run)
- Environment variable: `BUN_VERSION=1.4.5`

## Story and Facts

Page copy, Work entries, the profile, skills and the rest of the site's
content live in `src/content/`, written by hand.

Everything that is a version, a date or a count lives in `src/facts/`. Its
`snapshot.json` is generated by `bun run fetch-facts` and refreshed on a weekly
schedule in CI. Never edit `src/facts/` by hand; a hand-written fact is a bug.

## The CV

The public CV is built from the same content and published at `/cv.pdf`.
A fuller version, with fields that don't belong on the public site (full
name, phone, location), renders locally from `cv.private.env`, copied from
`cv.private.env.example` and filled in. Its output lives in `private/` and
is never committed or published.

## Verification

`bun run verify` runs type checks, an unused-code check with knip, the test
suites, a build and the output gates, and must pass before a change ships. `bun run lighthouse` runs the
performance, accessibility, best-practices and SEO budgets against a local
preview build. Both run in CI on every push and pull request, alongside a
link check of the built site.
